HAZEHUB ACCOUNTS
================================================================

Sign in with a Scouter ID plus the shared team password. The ID decides
what the account can do.

THE ACCOUNT LIST IS CLOSED. The seven accounts below are the only ones
that exist. They are written into the Firestore `scouters` collection
when the server starts. Typing any other ID is an error -- signing in
does not create an account any more, so a typo can no longer produce a
second, parallel account whose scouting nobody ever looks at again.

Shared team password:  HazeRain!
   Everyone types this, whatever their role. Change it before a real
   event: it is published in this repository. Set HAZEHUB_TEAM_PASSWORD
   on the server (backend/.env locally, or the Render dashboard).

There is NO separate picklist password. Picklists are controlled by
account role instead, so scouts can build their own lists without being
let into anything else.

----------------------------------------------------------------
THE SEVEN ACCOUNTS
----------------------------------------------------------------

  Scouter ID         Role        What it can do
  ----------         --------    ---------------------------------
  Admin              Admin       Everything. Event control, the match
                                 schedule, betting settings, film, and
                                 changing other people's roles.

  Strategy           Strategy    Everything an admin can do except
                                 changing roles. All analysis screens.
                                 Its picklists outrank scouter lists
                                 during the picklist meeting.

  PicklistMeeting    Picklist    The shared screen for a picklist
                                 meeting. Teams and picklists only, plus
                                 read-only access to the scouting behind
                                 an @match reference. It cannot advance
                                 the match, place a bet, or submit
                                 scouting, so a mis-tap on a projector
                                 cannot break anything.

  1, 2, 3            Scouter     Scouting accounts. Scout matches, pit
  Demo               Scouter     scout, bet, build their own picklists.

IDs are matched without regard to capitalisation, so "admin" and
"Admin" reach the same account. The spelling above is what gets stored.

Anyone who types an ID that is not on this list is told the account does
not exist and asked to check with an admin. The message deliberately
does not list the valid IDs: there is one shared password, so anyone who
could read that list could use it.

----------------------------------------------------------------
CHANGING THE LIST
----------------------------------------------------------------

Set HAZEHUB_ACCOUNTS on the server. Comma separated, `Id:role` per
entry, and a bare entry means scouter:

  HAZEHUB_ACCOUNTS=Admin:admin,Strategy:strategy,PicklistMeeting:picklist,1,2,3,Demo

Valid roles: scouter, strategy, admin, picklist.

To add the rest of the team, extend that list with their IDs:

  HAZEHUB_ACCOUNTS=Admin:admin,Strategy:strategy,PicklistMeeting:picklist,1,2,3,4,5,6,7,8,Demo

Restart the server and the new documents are created. Renaming an
account (including changing only its capitalisation) moves the existing
document across, keeping its Purple Bucks and scouting count.

----------------------------------------------------------------
CHANGING SOMEONE'S ROLE
----------------------------------------------------------------

Sign in as Admin, then Admin > Dashboard, or call the API directly:

  POST /api/admin/scouters/<scouter id>/role   {"role": "strategy"}

Admin only. Strategy accounts cannot promote anyone, and an admin
cannot demote themselves, so the team can never lock itself out.

----------------------------------------------------------------
BEFORE A REAL EVENT
----------------------------------------------------------------

1. Change HAZEHUB_TEAM_PASSWORD from HazeRain!.
2. Set HAZEHUB_SECRET to a long random string. It signs the login
   tokens; changing it signs everyone out, so do it beforehand and
   not mid-event.
3. Add the real scouts to HAZEHUB_ACCOUNTS, or they will not be able
   to sign in at all -- that is the point of the closed list.
4. Be aware of what the shared password means: anyone who knows it can
   sign in as "Strategy" or "Admin" and get those powers, because there
   is one password for the whole team. If that matters to you, rename
   those accounts to IDs your scouts will not guess (via
   HAZEHUB_ACCOUNTS above) or ask for per-role passwords to be added.
5. This file is committed to the repository. Do not put a real
   password in it.
